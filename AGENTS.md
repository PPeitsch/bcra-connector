## 0. Non-negotiable rules

These are the rules most often broken. Violating any of them invalidates the work.

| # | Rule |
|---|------|
| 1 | **Run `pre-commit run --all-files` before every commit.** If it rewrites files, stage them and run again until it exits 0. |
| 2 | **Run `pytest` before opening a PR.** |
| 3 | **Never merge with failing CI.** Fix it on the same branch. Never ignore or bypass a red check. |
| 4 | **Use the PR template** (`.github/PULL_REQUEST_TEMPLATE.md`) and complete the checklists honestly. |
| 5 | **Update `CHANGELOG.md`** under `## [Unreleased]` for any user-visible change. |
| 6 | **Never edit `src/bcra_connector/_version.py`** — it is generated by hatch. |
| 7 | **Always merge with `--delete-branch`.** Leaving the branch alive breaks re-targeting of stacked PRs, which then get no CI at all. |
| 8 | **Report failures honestly.** If a test fails or a step was skipped, say so explicitly. Do not claim success you have not verified. |

## 3. The one verification command

Run this before pushing anything. It is exactly what CI runs.

```bash
pre-commit run --all-files && pytest
```

`pre-commit` runs trailing-whitespace, end-of-file, YAML/TOML checks, merge-conflict
and debug-statement checks, then `black`, `isort`, `flake8` and `mypy`.

`pytest` skips the tests marked `integration` (they call the live BCRA API). Run them
with `pytest -m integration` when touching request/response handling; in CI they run
in `.github/workflows/integration.yaml` (manual and weekly), not on PRs.

> **Local and CI must agree.** If `pre-commit` passes locally but CI's Code Quality
> job fails, the hook's `additional_dependencies` have drifted from the pinned dev
> dependencies — fix the pin rather than working around the error.

## 4. Task workflow

### 4.1 Start
```bash
git status                 # workspace must be clean
git checkout main
git pull origin main       # never work from a stale main
```
Then read `CHANGELOG.md` (latest version) and `pyproject.toml` (current dependencies).

### 4.2 Branch
Naming: `type/issue-id-short-description`

Types: `feature`, `fix`, `docs`, `refactor`, `chore`

```bash
git checkout -b fix/issue-52-setuptools-vuln
```

Open an issue first if none exists — `CONTRIBUTING.md` requires one for any
significant change, and the branch name and PR body both reference it.

### 4.3 Commit

Format — **lowercase tag with a colon**, matching the repository's history:

```
[fix]: Concise description in 50 characters or less

Explain WHY the change is needed, wrapped at 72 characters. The diff
already shows what changed; use this space for motivation and context.

 - Bullet points are welcome

Resolves: #123
```

Valid tags: `[feature]:` `[fix]:` `[docs]:` `[refactor]:` `[chore]:` `[test]:` `[release]:`

### 4.4 Pull request

```bash
git push -u origin HEAD
gh pr create --base main --title "[fix]: ..." --body "..."
```

- Base the body on `.github/PULL_REQUEST_TEMPLATE.md` and complete the checklists.
- Start the body with the ⚡ token required by `CONTRIBUTING.md`.
- Reference the issue with `Fixes #N`.
- **One change per PR.** Do not bundle unrelated fixes.

### 4.5 Verify CI — mandatory

```bash
gh pr checks <PR_NUMBER>
```

**Never merge without green CI.** If a check fails, fix it on the same branch.
If a failure is pre-existing and unrelated, say so explicitly in the PR body with
evidence — do not silently ignore it.

```bash
# Only when every check passes:
gh pr merge --admin --merge --delete-branch
```

**Always delete the branch on merge** (`--delete-branch`, or the "Delete branch"
button in the web UI). This is not cosmetic:

> GitHub re-targets a **stacked** PR onto `main` only when its base branch is
> **deleted** on merge. Leave the base branch alive and the stacked PR keeps pointing
> at a merged branch, receives **no CI**, and silently rots. This happened with #86
> after #85 was merged without deleting.

> **Stacked PRs get no CI.** `.github/workflows/test-and-publish.yaml` triggers on
> `pull_request: branches: [main]`, so a PR targeting another branch receives **no
> checks at all**. Verify those locally and state that in the PR. After the base PR
> merges, confirm the stacked PR actually re-targeted to `main`:
> `gh pr view <N> --json baseRefName`. If it did not, re-target it manually with
> `gh pr edit <N> --base main`.

## 5. Release protocol

Releases are automated by tag push. **Never create a GitHub release manually.**
The full step-by-step SOP lives in **[WORKFLOW.md](./WORKFLOW.md)**; the summary:

1. Decide the new SemVer version.
2. Update `__version__` in `src/bcra_connector/__about__.py`
   (`docs/source/conf.py` reads it automatically — no manual edit).
3. In `CHANGELOG.md`: rename `## [Unreleased]` to `## [X.Y.Z] - YYYY-MM-DD`, add a
   fresh empty `## [Unreleased]`, and update the comparison links at the bottom.
4. Commit `[release]: Version X.Y.Z` on a `release/X.Y.Z` branch, open a PR, wait for
   CI and merge it. `main` is protected and the release commit is no exception: never
   push it straight to `main`.
5. Tag `vX.Y.Z` on the merge commit already on `main` and push the tag.
6. Confirm the "Test and Publish" workflow started for the tag.

## 6. Project overview

**bcra-connector** is a Python library providing a typed, robust interface to the public
APIs of Argentina's Central Bank (BCRA). No authentication is required.

See [`README.md`](./README.md) for features, installation and usage, and the
[BCRA API catalog](https://www.bcra.gob.ar/Catalogo/apis.asp) for the upstream endpoints.
Read the package layout from the source rather than from a diagram here: it goes stale.

Two conventions that the code does not make obvious:

1. **Dataclasses over dicts** — every API response parses into a typed dataclass.
2. **Fail-safe transport** — retry with exponential backoff is built in; do not add
   ad-hoc retry logic in the clients.

## 7. Code standards

- PEP 8, type hints on all public functions, clear docstrings
- `black` (line length 88) and `isort` (black profile) — enforced by pre-commit
- `mypy` must pass; the configuration is strict (`disallow_untyped_defs`)
- Tests required for every fix and feature
- **pandas is an optional extra** (`to_dataframe()`): any test touching it must use
  `pytest.importorskip("pandas")`
